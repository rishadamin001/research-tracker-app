## Compatibility and release boundaries

- Workspace envelopes 1 through 4 remain readable. Changed saves use envelope 4. IndexedDB and the project schema remain at version 1. Notebook rows and project history keep their current shapes.
- Plain portable backups still export as v3 and import v1, v2 and v3. Refusing excessively nested unknown data has no effect on records within the existing schemas. The encrypted container protects a v3 portable copy. Standard reference exchange remains bibliographic, while project backups carry judgments, drafts and notes.
- Learn practice, search history outside projects, preferences, and offline cache have their own local state. Existing project backups are not a full browser profile transfer. The host migration plan must test what it promises to preserve.
- Keep the published test and preview results tied to their revision. See the [security assessment](SECURITY-ASSESSMENT-0103.md), [backup design](ENCRYPTED-BACKUP-DESIGN.md), and [verification history](../TESTING.md).

The live-provider check remains separate from the deterministic release tests. Initial candidate runs paginated Europe PMC and Crossref for “Hypothyroidism” and failed at OpenAlex after HTTP 429. The 0.10.4 provider check passed separately; upstream availability can change.
