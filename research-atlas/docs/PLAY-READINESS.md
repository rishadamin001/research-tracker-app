## Run the public web preflight

Run this read-only check from the repository with Node.js. It needs no Play Console access or credentials.

```sh
node scripts/check-android-web-prerequisites.mjs https://rishadamin001.github.io/research-tracker-app/
```

The command checks the served manifest, start URL, app scope, 192 × 192 and 512 × 512 PNG headers, service-worker file and allowed scope, and the origin's Digital Asset Links response. Once the application ID and public SHA-256 signing certificate fingerprint are confirmed, pass them together with `--package APPLICATION_ID --fingerprint COLON_SEPARATED_SHA256` to check the exact association. The exit status is `0` when all checks pass, `1` for any failed or pending check, and `2` for invalid arguments. Browser registration, offline reopen, and Android fullscreen need separate tests on the corresponding browser or device.

On 17 November 2026, the public GitHub Pages site passed the manifest, start URL, scope, icon, and service-worker file checks. The origin-root `/.well-known/assetlinks.json` returned HTTP 404. The Android package and signing certificate are pending. Google's Bubblewrap 1.27.0 template targets API 36 and is a candidate for a pinned build once Android tooling is available. ## Hosting and signing decisions

1. **Start with a TWA using Bubblewrap.** It uses the device browser and reuses the PWA at its verified HTTPS origin. If file selection, offline storage or lifecycle behavior fails the phone tests, evaluate Capacitor and document the storage and native maintenance implications before changing wrappers. [Trusted Web Activities](https://developer.android.com/develop/ui/views/layout/webapps/trusted-web-activities)
2. **Confirm the launch origin before building the Play candidate.** The current project is served under `https://rishadamin001.github.io/research-tracker-app/`. For this origin, the Android association would have to be served at `https://rishadamin001.github.io/.well-known/assetlinks.json`. A file under `/research-tracker-app/.well-known/` does not establish that association. A project site deployment alone does not prove control of the origin root. Test the exact endpoint, HTTPS response, JSON content type, and absence of redirects. A replacement origin requires an owner decision and a tested export/import path. Keep the original site available so users can open the browser profile that still contains their data. [Digital Asset Links](https://developer.android.com/training/app-links/configure-assetlinks) · [Backup migration](BACKUP-MIGRATION.md)
3. **Use separate signing roles.** The upload key signs the AAB sent to Play. Play App Signing signs the installed Play APKs with the app signing key. Use the public SHA-256 app signing certificate fingerprint from the Console in production Digital Asset Links, alongside the approved package ID. Use the local APK’s actual signing fingerprint only for its authorized test origin or test setup. Keep keystores and passwords in owner-controlled secure storage. [Play App Signing](https://support.google.com/googleplay/android-developer/answer/9842756) · [Bubblewrap and association verification](https://developer.android.com/develop/ui/views/layout/webapps/guide-trusted-web-activities-version2)
4. **Check the installed Play build.** Confirm launch enters fullscreen trusted mode, scholarly links open correctly, and returning from an external site or file picker leaves the workspace intact. App installation alone does not exercise the web association or storage. Keep separate evidence for the locally signed APK and Play-delivered app. [TWA verification](https://developer.android.com/develop/ui/views/layout/webapps/guide-trusted-web-activities-version2)

## Privacy and Data Safety evidence

The current [public Privacy & data page](https://rishadamin001.github.io/research-tracker-app/#privacy) is the baseline. Before listing the Android build, verify that the policy opens in a standard public webpage without sign-in or regional restrictions, is clearly identified as a privacy policy, names Research Atlas or its listed developer, and includes an owner-confirmed privacy contact mechanism, retention, and deletion information. Provide the link in the app and the Play listing. A public issue tracker may suit general bug reports. Confirm an appropriate route for private privacy inquiries before publishing. [Privacy policy requirements](https://support.google.com/googleplay/android-developer/answer/9859455) · [User Data policy](https://support.google.com/googleplay/android-developer/answer/10144311)

| Flow to check in the actual build | Baseline evidence and declaration question |
| --- | --- |
| Local workspace and exports | Project data, questions, drafts, notes and snapshots are stored in browser storage. Exported files can contain private work. Check that the eventual policy reflects encryption as shipped, off-device export choices, deleting projects and snapshots, clearing site data, and separate copies on the filesystem. App account deletion is conditional on offering account creation. [Current privacy documentation](../PRIVACY.md) |
| Provider searches | Explicit user actions transmit entered search terms, supported filters, and relevant DOI, ISSN or work IDs to OpenAlex, Europe PMC or Crossref. Verify actual network requests, types, purposes and recipient behavior against the installed candidate. The user can enter sensitive content in a search field even when the app provides a warning. |
| Hosting and other links | The web host sees ordinary connection traffic. User-initiated scholarly search links can include the query, and calendar links can include selected event details. Classify these flows using the actual delivery configuration, applicable transfer exceptions in the Data Safety guidance, and available provider retention evidence. |
| Android wrapper and SDKs | Inspect final manifest permissions, build dependencies, and network traffic for SDKs, diagnostics, analytics, advertising, remote assets and optional services before reusing any web privacy description. Verify transport for relevant traffic and check the installed application and listing after every meaningful change. |

An app exclusively on the internal testing track is exempt from completing the Data Safety form. Closed, open and production tracks require it. Local research storage is consistent with off-device search requests. Derive the form from the complete launch-origin and wrapper inventory, Google’s definitions of collection and sharing, and verified exceptions. Do not infer a blanket declaration from the current local-first design. [Google Play Data Safety guidance](https://support.google.com/googleplay/android-developer/answer/10787469)
